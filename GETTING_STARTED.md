# Getting Started with WoWee

WoWee is a native C++ World of Warcraft client that connects to private servers. This guide walks you through setting up and playing WoWee.

## Prerequisites

- **World of Warcraft Game Data** (Vanilla 1.12, TBC 2.4.3, or WotLK 3.3.5a)
- **A Private Server** (AzerothCore, TrinityCore, Mangos, or Turtle WoW compatible)
- **System Requirements**: Linux, macOS, or Windows with a GPU and driver that support Vulkan 1.3 (MoltenVK on macOS), or Android 13+ on arm64

## Installation

### Step 1: Build WoWee

Prebuilt releases are on the [releases page](https://github.com/Kelsidavis/WoWee/releases/latest). To build from source, see the [Quick start](README.md#quick-start) in the README and the [complete build guide](BUILD_INSTRUCTIONS.md). The desktop build needs SDL3.

**Quick start (Linux/macOS)**:
```bash
./build.sh
cd build/bin
./wowee
```

**Quick start (Windows)**:
```powershell
.\build.ps1
cd build\bin
.\wowee.exe
```

### Step 2: Extract Game Data

WoWee needs game assets from your WoW installation, extracted to loose files.

**Using the asset builder (recommended)**:
- Start WoWee. With nothing extracted it opens the asset builder instead of the login screen.
- Choose your World of Warcraft folder and build. The assets go to the per-user data directory the client reads (see [Data Directory](#data-directory)).
- Close and reopen WoWee when the build finishes.

The same builder is under **more options** → **add or rebuild assets...** on the login screen, and ships as the standalone `wowee_assets` program. See [docs/asset-manager.md](docs/asset-manager.md).

**Using provided script (Linux/macOS)**:
```bash
./extract_assets.sh /path/to/WoW/Data wotlk
```

**Using provided script (Windows)**:
```powershell
.\extract_assets.ps1 "C:\Games\WoW-3.3.5a\Data" wotlk
```

The scripts write to `Data/` in the checkout, one directory per expansion (`classic`, `turtle`, `tbc`, `wotlk`):
```
Data/
└── expansions/
    └── wotlk/
        ├── manifest.json      # File index (generated by asset_extract)
        ├── expansion.json     # Protocol profile
        ├── dbfilesclient/     # DBC tables
        ├── interface/         # FrameXML, UI textures and icons
        ├── character/         # Character models and textures
        ├── creature/          # Creature models and textures
        ├── item/              # Item models and textures
        ├── spell/             # Spell effect models
        ├── world/             # Terrain, WMOs, doodads and maps
        └── sound/             # Audio files
```

### Step 3: Connect to a Server

1. **Start WoWee**
   ```bash
   cd build/bin && ./wowee
   ```

2. **Log In**
   - Pick your server from the **Server** list. ChromieCraft is listed, along with every server you have logged into
   - For another server, choose **Somewhere else...** and enter its address and port (default `3724`) under **more options**, where the expansion is set too
   - Enter your account and password and click **Log In**
   - Select your realm and click **Enter Realm**

3. **Choose Character**
   - Select an existing character, or click **New Hero** to create one
   - Click **Enter World**

### Customizing Controls

Press **Escape** → **Key Bindings** to customize hotkeys. The game's own Key Bindings panel lists every binding, including controller buttons.

### Using a Controller

A connected controller works on every platform. The left stick moves, the right stick looks, the triggers zoom, the bottom face button jumps and the right face button (or Start) acts as Escape. The other face buttons and the D-pad are action slots 1-6; hold the left bumper for 7-12. The right bumper targets the nearest enemy. **Back** turns the right stick into a mouse pointer for looting, gossip and vendors. Buttons are named for the pad you are holding (Xbox, PlayStation, Nintendo, Steam Deck), and look speed, inversion and deadzone are under Escape → **Interface** → **WoWee** → **Camera**.

## Recommended First Steps

This client's own settings sit under a **WoWee** heading in the game's Video, Sound and Interface panels.

### 1. Adjust Graphics Settings
- Press Escape → **Video** → **WoWee** → **Graphics**
- Select a **Quality preset** for your GPU:
  - **Low**: Low-end GPUs or when performance is priority
  - **Medium**: Balanced quality and performance
  - **High**: Good GPU with modern drivers
  - **Ultra**: High-end GPU for maximum quality (also grows grass)
- **Detail**, **Grass**, **Upscaling** and **Display** (fullscreen, vertical sync, frame rate limit, brightness) are beside it

### 2. Adjust Audio
- Press Escape → **Sound** → **WoWee** → **Sound**
- Set **Master volume** to preferred level
- Adjust music, ambience and the rest, with individual effects on **Sound Effects**
- Toggle **WoWee soundtrack** to hear or skip this project's own music

### 3. Configure UI
- Press Escape → **Interface** → **WoWee**
- **Minimap**: rotation, square minimap, clock, coordinates
- **Interface**: bag scale, separate bag windows, keyring, window scale, update check
- **Action Bars**: extra bars and their positions

### 4. Complete First Quest
- Talk to nearby NPCs (they have quest markers ! or ?)
- Accept quest, complete objectives, return for reward
- Level up and gain experience

## Important Notes

### Data Directory
Game data is looked for in this order:
1. `WOW_DATA_PATH`, if set
2. The per-user data directory, if it holds an extraction (this is where the asset builder writes):
   - macOS: `~/Library/Application Support/Wowee/Data`
   - Windows: `%LOCALAPPDATA%\Wowee\Data`
   - Linux: `$XDG_DATA_HOME/wowee/Data`, or `~/.local/share/wowee/Data`
3. `Data/` in the working directory. On Linux and macOS the client changes into its own directory at startup. `build/bin/Data` points at the checkout's `Data/`: CMake links it on Linux and macOS, and `build.ps1` makes a junction on Windows

### Settings
- Settings are saved to `~/.wowee/settings.cfg` (Linux/macOS)
- Or `%APPDATA%\wowee\settings.cfg` (Windows)
- A `portable.txt` file beside the executable keeps settings in a `config` folder next to it instead
- Keybindings (`bindings.cfg`), graphics settings, saved servers (`login.cfg`) and UI state persist

### Multi-Expansion Support
WoWee supports:
- **Vanilla 1.12** - Original game (and Turtle WoW 1.18)
- **TBC 2.4.3** - Burning Crusade
- **WotLK 3.3.5a** - Wrath of the Lich King

The expansion is not detected from the server. Each saved server remembers the expansion it was used with, and choosing it from the **Server** list selects that expansion; change it under **more options** → **Expansion** on the login screen. The selection is wired through `ExpansionRegistry::setActive()` (`src/ui/auth_screen.cpp`). There is no `WOWEE_EXPANSION` environment variable.

With more than one expansion's assets installed, an **Assets** row on the login screen chooses which set to draw with.

## Troubleshooting

### "No realm list" or "Connection Failed"
- Check server address is correct
- Verify server is running
- See [Troubleshooting Guide](TROUBLESHOOTING.md#connection-issues)

### Graphics Errors
- See [Graphics Troubleshooting](TROUBLESHOOTING.md#graphics-issues)
- Start with the Low quality preset
- Update GPU driver

### Audio Not Working
- Check system audio is enabled
- Verify audio files are extracted
- See [Audio Troubleshooting](TROUBLESHOOTING.md#audio-issues)

### No Assets / Asset Builder Opens Every Time
- The client found no extraction in any of the [data locations](#data-directory)
- Build the assets in the builder, then close and reopen WoWee
- If you extracted with the scripts, the data is in the checkout's `Data/`; set `WOW_DATA_PATH` to it when running a client that is not `build/bin/wowee`

### General Issues
- Comprehensive troubleshooting: See [TROUBLESHOOTING.md](TROUBLESHOOTING.md)
- Check `logs/wowee.log` in the working directory for errors. If that directory cannot be written (for example an installed macOS app), the log goes to `~/Library/Logs/Wowee` on macOS, `%LOCALAPPDATA%\Wowee\logs` on Windows, or `$XDG_STATE_HOME/wowee/logs` (default `~/.local/state/wowee/logs`) on Linux, and the path is printed to the console
- `WOWEE_LOG_LEVEL=info` (or `debug`) writes more than the default warnings and errors
- Verify expansion matches server requirements

## Server Configuration

### Tested Servers
- **AzerothCore** - Full support, recommended for learning
- **TrinityCore** - Full support, extensive customization
- **Mangos** - Full support, solid foundation
- **Turtle WoW** - Full support, 1.18 custom content

### Server Requirements
- Must support Vanilla, TBC, or WotLK protocol
- Warden anti-cheat supported (module execution via emulation)
- Network must allow connections to realm list and world server ports

## Tips for Better Performance

- Start with reasonable graphics preset for your GPU
- Close other applications when testing
- Keep GPU drivers updated
- View distance is the single largest cost; lower it first
- Use FSR 1 or FSR 3 upscaling (Video → WoWee → Upscaling) on weaker hardware
- Cap the frame rate under Video → WoWee → Display to save power and heat
- Debug builds show a performance HUD on F1
